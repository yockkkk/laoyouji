# PRD · 老友记 — 老年人多智能体生活助手

> 版本 v2.0 · 2026-09-01 · 竞赛原型（Prototype）
> v2.0 = 大改版。v1.0 的功能范围没变，变的是"卖点在代码里是机制还是布景"。本文件凡是能被代码钉住的数字与话术，都已按代码核对过；核不上的已订正，见 §11。

## 1. 一句话定位

一套以**语音优先**的多智能体系统，覆盖老年人**生活、出行、健康、社区**四大核心场景；总智能体「老友记」统一接收自然语言指令并调度子智能体，**安全管控中间层**保障高危操作必须经子女确认后执行。

## 2. 用户画像

| 角色 | 画像 | 核心诉求 |
|---|---|---|
| 老人（主用户） | 65-80 岁，慢性病（如腿疼/骨关节炎），不擅长 App 操作，部分使用方言（如西南官话） | 动动嘴就把事办了；听得懂；不被骗 |
| 子女（付费决策者） | 30-50 岁，异地工作，无法随时陪护 | 远程守护父母安全；关键操作把关（防误操作/防诈骗） |

演示默认家庭：**张桂芳**（老人，南京，慢性骨关节炎，方言偏好 `southwestern`）— **李明**（儿子，北京，已绑定）。名字取自 `app/db/seed.py`，交付物标题直接用它，**文档与 PPT 里不要写成别的字**。

## 3. 系统角色（智能体拓扑）

```
                    老人（语音/文字）
                          │
                  ┌───────▼────────┐
                  │ 总智能体·老友记  │  意图识别 / 任务规划 / 并行调度 / 结果聚合
                  └───────┬────────┘
        ┌─────────────┬───┴───────────┬─────────────┐
   ┌────▼─────┐  ┌────▼─────┐  ┌──────▼──────┐      │
   │ 银发导航  │  │ 安康助手  │  │   邻里帮     │      │
   │ 出行子Agent│  │ 健康子Agent│  │ 社区服务子Agent│    │
   └────┬─────┘  └────┬─────┘  └──────┬──────┘      │
        └─────────────┴───┬───────────┴──────────────┘
                  ┌───────▼────────┐
                  │  安全管控中间层  │  高危拦截→子女确认 / 方言ASR / 大白话引擎 / 隐私分级
                  └───────┬────────┘
                          │
              子女端（确认 / 守护 / 告警）
```

### 3.1 总智能体「老友记」

- 接收老人全部自然语言指令，做意图识别与澄清追问（`ask_user`，一次只问一个）
- 动手前用 `todo_write` 写下清单，落 `todo/write` 事件 → 老人端步骤条。**清单内容由模型按当次任务写**，不是写死的五步；步骤条只渲染快照，不自己推进
- 用 `delegate` **成批**派活 → `subagents.run_parallel`，能同时干的一次派多个（跨城就医第一波：health 查医院挂号 + travel 查车次，同时派）
- 用 `compose_deliverable` 出交付物：读回本会话所有 `agent/report`，套 `plan_builder` 模板渲染。**模型不参与拼字典**
- 闲聊、情绪陪伴、简单问题直接回答，不派发

四件工具一一对应架构里的一条承诺 —— 这是"真调度器"和"会说自己在调度的助手"的区别。

### 3.2 出行子 Agent「银发导航」

工具：`search_train` 查车票 · `book_ticket` 订票 · `search_hotel` / `book_hotel` 酒店 · `plan_route` 路线规划 · `hail_ride` 叫车 · `get_weather` 天气 · 行程守护（位置上报 → 偏航/久留/未到达 → 告警推子女端）

`report_schema = ("ticket", "hotel")` —— 计划书第二、三页的来源。

### 3.3 健康子 Agent「安康助手」

工具：`search_hospital` 找医院 · `register_appointment` 挂号引导 · `interpret_report` 体检报告大白话解读 · `add_medication` 用药提醒计划 · `check_scam` 反诈识别 · `diet_advice` 饮食推荐

`report_schema = ("appointment",)` —— 计划书第一页的来源。

### 3.4 社区服务子 Agent「邻里帮」

工具：`canteen_order` 社区食堂订餐 · `order_service` 保洁/陪诊下单 · `query_order_status` 订单进度 · `push_activities` 社区活动推送

`report_schema = ("service_order",)` —— 《社区服务预约单》的来源。

> **`report_schema` 是"这个子 Agent 欠哪几个字段"的声明。** 交完差把字段填齐，缺的进 `report.missing`，一路传到卡面上的"待补"。三个子 Agent 都另带 `plain_say`（大白话引擎是公共组件，不各自实现）。

### 3.5 安全管控中间层（竞赛加分模块）

三条能力，各有代码落点：

**① 高危操作拦截 → 子女确认**（`safety/risk_rules.py` + `safety/confirmation.py`）

- 高危工具集 `{book_ticket, book_hotel, register_appointment, pay, order_service}` **一律拦截，与金额无关**
- 不在名单里的工具，参数金额 **≥ 50 元**也拦（`PaymentRiskRule(amount_threshold=50.0)`）；金额 ≥ 50 时 `risk_level` 记 `high`，否则 `medium`
- 挂起那一刻**冻结 `tool_args`**；子女批准后精确比对再新建 `TurnContext` 重放。参数被改过一个字就拒绝执行
- 30 分钟未处理 → 惰性清扫为 `expired`
- **fail-closed**：找不到应答者（没绑定子女）直接 deny，不等超时。等超时等于"没人管就默认放行一段时间"

**② 公共组件**：方言 ASR（讯飞）、大白话翻译引擎（`shared/plain_language.py`）—— 所有子 Agent 共用，不各自实现

**③ 数据隐私分级**（`safety/privacy.py`）：位置 `realtime / city / off`、健康 `full / summary / off`，由老人掌控。降级方式是**数据变形**（字段还在，值换成 MASKED、精度削粗，另附 `precision` 标记），不是报错 —— 报错会让子女去催老人"把权限全开"，正好把分级机制废掉

## 4. 旗舰场景（演示主线）

**"我想去北京看腿疼的老毛病。"** →

1. 主智能体识别意图 → 必要时澄清（哪天出发）→ `todo_write` 写清单，老人端步骤条出现
2. **同时**派 health（查骨科医院 + 号源）与 travel（查南京南→北京南车次）—— 事件时间戳重叠，不是排队
3. 挂号（积水潭骨科，田伟 100 元 / 刘心 60 元，按选定医生）→ **拦截**，发起子女确认
4. 订票（G102 二等座 553.5 元）→ **拦截**；订医院附近无障碍酒店 → **拦截**；查天气
5. 子女端弹出待确认卡 → 点【同意】→ 系统重放冻结的调用 → 出票/挂号成功
6. `compose_deliverable(kind=trip_plan)` → **《张桂芳 · 北京就医出行计划书》**，五页固定页序：

   | 页 | 内容 |
   |---|---|
   | 第一页 | 挂号信息（医院/科室/医生/就诊时间/时段/挂号费/地址/**状态**） |
   | 第二页 | 去程车票（车次/日期/站/时刻/座位/票价/**状态**）+ 返程建议 |
   | 第三页 | 酒店（名称/地址/电话/到医院步行/入住/晚数/房费/无障碍/**状态**） |
   | 第四页 | 随身清单（身份证/医保卡/病历片子/老花镜/常备药，按天气追加伞与厚外套） |
   | 第五页 | 目的地天气与穿衣建议（含"要不要带伞"） |

   "**状态**"行就是子女确认的落点，取值只有三种：已办好 / 已选定，等家人在手机上点"同意"后锁定 / 家人这次没同意。它来自结构化字段，不是模型措辞。
7. 出行日：行程守护演示一次偏航告警推子女端

**这份计划书的每个字段都可以逐条指认来源。** 评委问"这个 553.5 是哪来的"，答案是 `search_train` 的结果经 `AgentReport.data` 采集、由 `plan_builder` 按标识符连接后印上去的，不经过模型措辞。取不到的字段渲染"待补"并回填 `missing` —— 人为抽掉酒店 report，第三页就该明明白白写"待补"，而不是编一个地址。

## 5. 功能黑名单（红线，任何情况下不得突破）

| # | 红线 | 代码落点 |
|---|---|---|
| R1 | **不做 AI 医疗诊断**。症状→科室仅是就医引导；报告解读是"通俗化翻译"不是医学结论 | 提示词 + `install_medical_safety`（见下） |
| R2 | **不做处方建议**。不推荐具体药物/剂量，只管理"医生已开"的用药提醒 | 同上 |
| R3 | **不触碰真实资金**。支付全部走 Mock Provider，任何扣款动作必须先过子女确认 | `providers/external/payment.py` + 确认流 |
| R4 | **健康类输出强制带免责声明**，由代码注入，不依赖 LLM 自觉 | `HealthDisclaimerGuard`（`tools/post-execute`） |
| R5 | **不做无人监护的自动执行**。高危工具集一律拦截 | `PaymentRiskRule` → INTERCEPT |
| R6 | 隐私数据不越级：子女可见范围严格按老人授权的分级 | `safety/privacy.py` 裁剪出库数据 |

### R1/R2 的最后一道：诊断口吻整句改写

提示词里写了"绝不诊断"，但提示词是**请求**，不是**保证**。`install_medical_safety(bus)` 把 `diagnosis_scrubber` 挂在 `agent/request` 瀑布的**最外层**（`order=-100`），所以它看到的是所有重试、所有其它中间件之后的最终应答 —— 谁也绕不过它。

- 命中"您这是××病 / 确诊 / 诊断为"→ 整句换成"这我不能替医生下判断，得让大夫当面看看才算。"
- 命中剂量或"××药"的用法建议 → 换成"吃什么药、吃多少，得听医生的，我不能给您定。"
- **整句替换而不是抠词**：抠词会留下"您这是…（已隐去）"这种更吓人的残句
- 饮食建议不误杀：处方模式刻意要求出现剂量单位或"药"字才算命中，"建议吃点清淡的"照常放行 —— 饮食推荐是本项目的正常能力
- `scrub_medical_text()` 是纯函数，可以在答辩现场当场演示"输进去一句诊断，出来是什么"

**一个诚实的边界**：流式 `delta` 由 provider 内部逐片推送，比改写更早到前端，所以打字预览可能是未审原话。预览 `persist=False`（不进事件日志、不进模型历史、不进审计）；进日志的、以及前端最终定稿的那条气泡，都是改写后的 `agent_msg`。**前端必须用 `agent_msg` 覆盖预览** —— 这条契约写在 `docs/DESIGN.md` §6.1，由 `test_medical_safety.py::test_the_streaming_preview_is_not_the_authoritative_text` 钉住。

### R4 的实际文案

```
（以上是把报告上的话换成大白话，属于辅助解读，不是诊断结论。
  身体的事请听医生的，遵医嘱。）
```

口径按要求收紧：**明说"辅助解读、不做诊断"**，不让人误读成"AI 看过就算看过病"。注入范围是 `HEALTH_TOOLS = {interpret_report, diet_advice, register_appointment, search_hospital, check_scam}` 的成功结果，写进 `summary` 与 `announce` 两个字段（已含"遵医嘱"或"不能替代"的不重复注入）。

计划书另有一条自己的声明（`plan_builder.DISCLAIMER`）："本计划书由老友记根据查询结果自动生成，仅供出行参考。医疗相关内容不构成诊断意见，请以医生面诊结论为准。"

## 7. 交互与适老规范

- **字号 ≥ 20px**（`$lyj-font-md: 40rpx`；`750rpx ≡ 视口宽`，375pt 屏上 1rpx = 0.5px）、**主按钮 ≥ 80px**（`160rpx`）、**麦克风 120px**（`240rpx`），高对比配色

- 「再念一遍」在对话气泡与交付卡片上都有（H5 `speechSynthesis`，语速 0.85）。卡片的朗读文本由前端从**卡面**合成 —— 后端的 `announce` 字段不随 `card` 事件下来
- 所有面向老人的话术经过**大白话引擎**（短句、无专业术语）
- 老人端 4 页进原生 `tabBar`；子女端顶部分段控件 + 页面栈，**返回键必须可用**（全仓禁用 `uni.redirectTo`）

## 8. 演示数据披露声明（必写进答辩）

> 本竞赛原型中，挂号平台、12306 车票、支付、酒店、天气、地图、社区服务等外部服务均采用**模拟数据**（个人开发者无法获取上述平台的正式接口）。系统接口层已按 Provider 适配器模式预留接缝，正式落地时替换为官方开放 API 即可，业务逻辑无需改动。

这句话有三个落点，都必须在：`README.md`、答辩稿、以及**计划书自己的脚注**（`plan_builder.MOCK_NOTE` → `card.footnote` → 卡片脚注）。第三个落点返工时才补上 —— 后端印了、前端没取，等于没披露。

## 9. 市场可行性（评分维度五）

- **To C**：子女端年费订阅（参考定价 199 元/年）——"给父母请了个 AI 秘书"

## 11. v1.0 → v2.0 的事实订正

写在这里而不是静静改掉，因为这几个数字很可能已经进了 PPT：

| v1.0 的说法 | 实际 | 依据 |
|---|---|---|
| 挂号费 50 元 | 积水潭骨科：田伟 **100 元**、刘心 **60 元**；风湿免疫科穆荣 80 元 | `app/data/hospitals.json` |
| 大额下单 **>** 50 元触发拦截 | **≥** 50 元；且高危工具集**与金额无关，一律拦截** | `risk_rules.py:50,60,63` |
| 步骤条 = 固定五步（①选医院…⑤天气） | 清单由模型按当次任务写，步数不固定；界面只渲染快照 | `main_agent.SYSTEM_PROMPT` 第 2 条 |
| 计划书含"费用明细/子女已确认标记"两栏 | 没有独立栏目。费用分散在各页（挂号费/票价/房费），确认状态是每页的"状态"行 | `plan_builder.py` 五个 `_page_*` |
| 30 分钟超时过期是唯一兜底 | 另有 **fail-closed**：无应答者即 deny | `safety/confirmation.py` |
| 计划书标题《XX老人 · …》 | `f"{name} · {city}就医出行计划书"`，**无书名号、无"老人"二字** | `plan_builder.py:302` |
