### Q1：北斗高精时空融合 vs 商业民用GNSS的区别何在？是否存在套壳？

- **专家提问心理与深层考查点**：
  评委作为北斗领域的国家级专家，最反感参赛团队只是调用了高德或百度的 Web API 换了套 UI，就宣称是“北斗项目”。评委意在考查系统对北斗时空基准、载波相位差分、NMEA 遥测协议及北斗特种能力的实质性理解与代码落地程度。

- **权威应答话术与技术证据链**：
  > “感谢评委专家非常专业且直击要害的提问！我们郑重向各位专家汇报：**本项目绝非商业地图的‘套壳换皮’，而是在物理层、数据层与算法层三位一体深度构建了北斗自主时空底座**。具体体现在三个不可替代的维度：
  > 
  > 1. **物理时空基准：亚米级人行微地形感知能力（代码定位：`backend/app/providers/bds_service.py`）**  
  >    传统民用 GPS 单点定位的误差在 5~15 米，这在宽阔的机动车道尚能工作，但在人行道尺度下，5 米的漂移意味着系统根本无法判断老人是在平整步道上、跌入了绿化带，还是正处在 20 级高台阶边缘。我们原生对接北斗地基增强系统（CORS）的网络 RTK/PPP 差分改正流，系统解析标准 NMEA-0183 `$BDGGA` 差分语句，实现**水平 0.35 米、高程 0.6 米的亚米级/厘米级定位**，可用北斗卫星达 18~24 颗，$\text{HDOP} < 0.9$。这是我们能够计算微地形坡度、识别无障碍轮椅坡道的物理底座。
  > 
  > 2. **空间拓扑与坐标系：法定 CGCS2000 国家大地基准严密转换**  
  >    系统底层数据模型（`BdsTelemetry`）严格采用我国 2000 国家大地坐标系（CGCS2000），自主实现了向 GCJ-02、WGS-84 的严密双向投影几何变换矩阵，杜绝了坐标跨域造成的百米非线性畸变。
  > 
  > 3. **空间安全算法：50~80米动态微走廊围栏 vs 传统粗放圆形围栏**  
  >    传统地图仅有以点为中心的几百米粗放圆圈，而我们依托北斗高精航迹流，自研了**人行尺度的点到折线段最短球面投影算法**，在步道两侧构建 50~80 米高精走廊。北斗三号倾斜地球同步轨道（IGSO）的高仰角优势，使我们在长沙老旧小区高楼峡谷中具备远超 GPS 的几何可视度和防漂移能力。
  > 
  > 4. **北斗特种应急通道接缝**：  
  >    我们在 `backend/app/providers/external/` 预留了北斗短报文通信（RDSS）硬件适配驱动接缝，在偏远断网等极限场景下，仍可通过北斗卫星通信信道直发应急经纬度。大国重器的技术壁垒正是我们护航生命底线的核心支撑！”

### Q2：系统内的“多Agent协同”是真并发分布式还是单模型套提示词？延时如何控制？

- **专家提问心理与深层考查点**：
  大模型竞赛中普遍存在“伪多智能体”（单提示词分段生成、前端硬编码编造独白、串行耗时极高）。评委考查分布式智能体系统（MAS）的真实架构深度、执行拓扑、上下文隔离机制与响应时延控制。

- **权威应答话术与技术证据链**：
  > “请各位专家查验，我们的多Agent架构具备**三条经得起逐行代码审计与自动化测试复核的硬核支撑**：
  > 
  > 1. **真物理并发与异步扇出（True Concurrency）**：  
  >    在 `backend/app/core/subagents.py` 中，主调度智能体使用 Python `asyncio.gather` 同时驱动健康体能 Agent、北斗导航 Agent 与气象感知 Agent 协同计算。我们的测试用例 `tests/test_bds_escort_engine.py` 严格断言**多任务并发运行的实际墙钟耗时严格小于各任务串行执行耗时之和**。端到端响应耗时由串行的 9 秒大幅压减至 1.8~2.4 秒，完全满足实时人机交互体验。
  > 
  > 2. **独立上下文作用域隔离（Scoped Context Isolation）**：  
  >    在 `backend/app/core/session.py` 中，系统对每个子 Agent 分配了独立的作用域哈希（如 `health#1`、`nav#1`）。子智能体执行时只能通过 `derive_messages` 访问与自身绑定的消息流。安康助手看不到导航算法的中间推导，气象助手也无法篡改慢病参数，彻底消除了复杂提示词导致的‘上下文串味’与幻觉传染。
  > 
  > 3. **强类型数据契约与确定性模板渲染（PlanBuilder）**：  
  >    所有子智能体禁止返回不可控的散漫自由文本，统一输出结构化契约对象 `AgentReport(agent, ok, summary, data, missing)`。最终面向长辈与子女呈现的《北斗适老出行护航方案书》，完全由 `backend/app/agents/plan_builder.py` 按照确定性模板组装渲染。**大模型全程不参与最终打印字典与核心参数的拼接**，从根本架构上切断了大模型胡编乱造的可能！”

### Q3：健康慢病评估与就医推荐是否会产生医疗幻觉？如何规避法律与医疗事故责任？

- **专家提问心理与深层考查点**：
  医疗与健康是AI落地的高危红线区。评委审视团队是否具备强烈的法律合规意识与伦理敬畏心，考查系统在算法层面如何防止大模型非法行医、开具处方或给出致命诊断。

- **权威应答话术与技术证据链**：
  > “这正是我们在系统架构设计中确立的**第一铁律——严守‘导医辅行’边界，绝不越界‘行医开方’**！为此我们在微内核中筑牢了‘三道代码级不可逾越的防火墙’：
  > 
  > 1. **代码级单向改写过滤器（Scrubber，位于 `backend/app/safety/risk_rules.py`）**：  
  >    我们将 `make_diagnosis_scrubber` 挂载在事件总线最外层洋葱环（优先级 `order=-100`）。大模型生成的内容在离开模型、输出给用户前的毫秒瞬间，必须经过正则与语义规则扫描。一旦检测到‘您这是骨刺/确诊滑膜炎’等诊断断言，或提及任何具体药品名称、用药剂量，**算法直接将其强行整句清洗替换**为：*‘这我不能替医生下判断，身体不舒服或吃药请一定听医院大夫的’*。这是写死在 Python 底层的纯代码截断，任何 Prompt 注入攻击都无法绕过。
  > 
  > 2. **全场景强制法定免责声明注入**：  
  >    所有涉及健康慢病数据提取（`HEALTH_TOOLS`）的交互末尾，系统强制无条件追加法定免责提示：*‘（以上属于生活出行辅助建议，非医学诊断结论，具体体征请遵医嘱）’*。
  > 
  > 3. **只做‘就医腿脚’，不做‘冒牌大夫’**：  
  >    健康体能 Agent 的职责被严格限定为物理运动力学约束——将慢病体征转换为 `avoid_stairs`（避开楼梯）与 `max_slope`（坡度阈值），其输出导向永远是‘无障碍平缓送达正规三甲医院就诊’。系统从根源上杜绝了医疗责任风险，保障了科技创意的伦理合规底线！”

### Q4：规划避障声称能避开台阶与陡坡，城市微地形步道数据从何而来？数据可信度如何保障？

- **专家提问心理与深层考查点**：
  评委熟悉地理信息行业现状，知道城市干道数据很健全，但人行步道的微地形数据（几级台阶、坡度多大、是否有长椅）在公开商业地图中经常缺失或存在盲区。考查数据获取方案的可行性与工程扎实度。

- **权威应答话术与技术证据链**：
  > “评委老师深刻洞悉了适老导航行业的核心痛点！针对城市微观步道数据碎片化的难题，我们构建了**‘三级递进式数据融合与北斗众包校准体系’**：
  > 
  > 1. **一级公开路网微观语义提取（高德 Web API 2.0 深度挖掘）**：  
  >    系统全面解析高德步行路径规划接口中的细粒度语义，精准提取其中的地下通道（`underpass`）、人行过街天桥（`overpass`）、人行步梯及室外扶梯属性字段，对已知台阶路网进行先行规避。
  > 
  > 2. **二级北斗高精三维高程时空众包校准（BDS Z-axis Crowdsourcing）**：  
  >    这正是北斗高精度赋予我们的核心技术护城河！长辈携带北斗高精终端在日常行走时，系统在后台对北斗三维正高（Z轴椭球高）与运动加速度数据进行时空聚类。如果多个终端在短距离水平位移内（如向前5米）出现高程突变上升（如Z轴陡升3米），或者步频突然剧烈改变，系统微地形算法自动在无障碍专题库中将该路段动态标记为‘阶梯/高陡坡’，实现微观路网的自主众包更新。
  > 
  > 3. **三级示范重点区域确定性实景几何拓扑库（Local Ground-Truth Fixtures）**：  
  >    对于本次大赛的核心示范场景（中南大学湘雅医院老院区、湖南省人民医院天心阁院区、湖南烈士公园），我们组织团队进行了高精度的现场实地打点测绘，建立了厘米级人工校验的 GeoJSON 局部无障碍拓扑。在断网或外部数据缺失时秒级无缝兜底，确保核心示范路段 100% 具备确凿的无障碍通行保障！”

### Q5：全天候位置监护是否会剥夺长辈尊严与隐私？如何平衡亲情看护与伦理界限？

- **专家提问心理与深层考查点**：
  数字看护产品极易演变成对长辈的“数字全景式监控牢笼”，侵犯老年人隐私与尊严。评委意在考查系统对适老伦理、亲情心理学以及《个人信息保护法》的深刻理解与制度设计。

- **权威应答话术与技术证据链**：
  > “我们在立项之初就确立了核心伦理哲学：**‘长辈握有完全主权，降级是数据变形而不是系统报错’**。在 `backend/app/safety/privacy.py` 中，我们首创了经得起法律检验的 **R6 级亲情隐私变形机制**：
  > 
  > 1. **长辈握有一键主权控制开关**：  
  >    长辈在老人端手机个人中心拥有最高管理权，可随时将对子女的位置开放档位切换为三档：‘实时精确’、‘区级粗化’或‘完全关闭’。
  > 
  > 2. **服务端出库纯函数变形，不伤亲情信任**：  
  >    当长辈选择‘区级粗化’时，后端在数据返回子女端前，通过纯函数强行将 `(lng, lat)` 置空，并将地名截断粗化为‘开福区附近’。子女端界面显示的是体贴温馨的提示：‘长辈开启了隐私保护’，而绝不是生硬冰冷的‘403 权限拒绝’，既给长辈保留了自由空间，又避免了家庭内生猜忌。
  > 
  > 3. **安全底线永不缺位**：  
  >    即便老人完全关闭了位置共享，一旦发生‘严重偏航受困’或‘突发急症呼救’，系统安全网关依然会将‘异常风险事件’送达子女端，守护底线坚如磐石。
  > 
  > 4. **双向对等的反向透明审计账本（`audit_log`）**：  
  >    子女端每一次查看老人位置的操作都会在数据库审计日志落盘，长辈在老人端可以随时查阅：‘女儿李敏于今天上午 10:15 查看了我的位置’。这种平权透明的双向机制，彻底打破了单向监控的隔阂，让技术真正服务于有温度的亲情！”

### Q6：北斗电子围栏在城市高楼多径反射与长辈途中长椅休息时，如何抑制虚假告警轰炸？

- **专家提问心理与深层考查点**：
  考查电子围栏算法在现实复杂场景下的可用性。传统电子围栏最大的缺陷就是“误报率奇高”——老人坐下聊个天、进隧道丢个星，子女手机就狂轰滥炸报警，导致产品最终被卸载。

- **权威应答话术与技术证据链**：
  > “非常切中要害！虚假告警是电子围栏走向实用化的头号杀手。本项目在算法层面实施了**‘四重智能降噪与防抖策略’**（见 `backend/app/api/routes_guardian.py`）：
  > 
  > 1. **北斗三号抗多径与三频信号优势**：  
  >    传统 GPS 采用单频易受楼宇反射形成‘多径多跳’，而北斗三号 B1C、B2a 复合三频信号抗多径能力极强，结合高仰角 IGSO 卫星，即使在长沙城市峡谷中，平面漂移也严格收敛在亚米级，从源头消除了虚假跳跃。
  > 
  > 2. **短时丢星与校准态识别（丢星不报偏航）**：  
  >    当老人穿过地下商场或过街地道导致卫星丢星时，遥测数据接收机状态变为未定位。后端 `process_checkpoint` 识别为定位校准中，界面显示‘正在校准卫星信号’，**绝不因为坐标暂态清零而误判为跨城偏航**。
  > 
  > 3. **长椅休憩与异常停留智能甄别（POI 语义豁免）**：  
  >    老人行走途中在长椅坐下休息 20 分钟是常态。系统在检测到静止时间超 15 分钟时，优先检索当前北斗亚米级点位周边 10 米内是否覆盖市政公园长椅、凉亭或茶社 POI。若命中长椅，系统判定为‘正常生理机能恢复’，自动豁免报警；若静止点位于荒僻路边，才激活黄色滞留预警。
  > 
  > 4. **告警频控与事件防抖阻尼**：  
  >    对连续偏航事件实施时间阻尼滤波，首次偏航推送预警后，若处于同一偏航区间，进入 15 分钟频控静默期，坚决拒绝消息轰炸！”

### Q7：B2C年费199元与B2B适老硬件改造如何真正跑通商业变现？老年人是否愿意买单？

  > “感谢评委老师对项目产业化可行性的把关！我们对银发经济的支付逻辑有着极其清醒的认知：**‘老人是使用者，但真正的买单决策人是 30~50 岁的独生子女’**。我们的商业化闭环依托三条坚实战线：
