## 五、Android APK 原生轻量化构建原理解析

本项目摆脱了传统 Android 编译对数 GB 体积 Gradle 与 Android Studio 的依赖，采用基于 Google 官方底层工具链的极速封装方案：

```
[前端 Vue 3 构建] ──> [生成原生 Android 工程] ──> [aapt 编译资源]
                                                        │
[交付 laoyouji.apk] <── [apksigner 签名] <── [zipalign 4字节对齐] <── [javac + D8 转 DEX]
```

### 1. 核心流程与工具链
1. **容器层（MainActivity.java）**：构建原生 Android Activity，挂载全屏 Hardware-Accelerated WebView，在 Java 层穿透麦克风与 GPS 定位权限；
2. **资源编译（aapt）**：读取 `AndroidManifest.xml` 与布局生成 `R.java`，打包基础资源；
3. **源码编译（javac + D8）**：基于 `android.jar (API 30)` 将 Java 源码转为 `.class`，随后通过 D8 编译器转为 Android 原生虚拟机指令 `classes.dex`；
4. **字节对齐（zipalign -p -f 4）**：**关键步骤**。强制使 APK 内部的 `resources.arsc` 按 4 字节边界对齐，彻底杜绝 Android 11+ 系统直接 mmap 内存映射失败报 **`-124` 错误**；
5. **官方签名（apksigner）**：注入自签 RSA 证书，一次性打通 **v1（JAR）、v2（APK Signing Block）与 v3（密钥轮转）** 三重签名校验。

### 2. 本地重新编译指令（如需重新打包）
在服务器上只需执行封装好的自动化构建脚本：
```bash
/opt/laoyouji/build_apk.sh
```
执行后 3 秒内即可在 `/opt/laoyouji/backend/static_dist/laoyouji.apk` 重新生成已对齐并签名的最新安装包。

## 六、本地 Docker 容器化编排运行指引

为了实现开箱即用并彻底规避 Windows / Linux 开发环境差异，本项目现已全面支持基于 Docker Compose 的容器化运行。

### 1. 容器架构规划
* **前端容器 (`laoyouji-frontend`)**：基于 Node 20-alpine 镜像，托管 Uni-app H5 开发环境，宿主机映射端口 `5174:5174`，通过内置 Vite Proxy 将 `/api` 请求无缝反代至后端容器。
* **后端容器 (`laoyouji-backend`)**：基于 Python 3.12-slim 镜像，运行 FastAPI 高并发多智能体内核，宿主机映射端口 `8000:8000`。
* **双容器私有桥接网络 (`laoyouji-net`)**：前后端容器通过内网别名互联，具备健康检查探针 (`healthcheck`) 与开机自愈能力。

### 2. 一键极速控制脚本（Windows 批处理）
项目根目录下提供了 4 个零门槛批处理脚本，双击即可完成常用操作：

| 脚本文件 | 功能说明 | 对应标准命令 |
| :--- | :--- | :--- |
| `docker-start.bat` | 一键构建并后台启动全套前后端微服务 | `docker compose up -d --build` |
| `docker-stop.bat` | 一键平滑停止并注销容器 | `docker compose down` |
| `docker-logs.bat` | 实时查看前后端容器交互聚合日志 | `docker compose logs -f` |
| `docker-test.bat` | 在隔离后端容器内一键执行 Pytest 自动化测试 | `docker compose exec backend pytest` |

### 3. 本地验证与访问
容器启动成功后，浏览器直接访问：
* 前端体验页面：`http://localhost:5174`
* 后端健康检查：`http://localhost:8000/api/health`（返回 `{"ok":true,"providers":{...}}`）
* Swagger 接口文档：`http://localhost:8000/docs`
