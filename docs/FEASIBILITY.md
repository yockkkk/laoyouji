## 0. 结论先行:"全真"不是一件事,是三种机制

上一版的承重发现是:**纯 H5 里"app 不开就够不到人",所以主动问候/及时通知/用药提醒/后台守护物理不可行。** 你选择打 APK 来解锁它们 —— 方向对。但**打了 APK 不等于这四件事就一起变真了**。它们背后是三种完全不同的技术机制,难度、真实度、敌人各不相同。把它们混为一谈,就会重蹈"以为开个接口就行"的覆辙。

| 机制 | 触发方式 | 对应功能 | APK 里怎么做 | 能做到多真 | 真正的敌人 |
|---|---|---|---|---|---|
| **① 时间驱动** | 到点 | 用药提醒、晨间问候 | **已真做**:`android/` 原生 `AlarmManager` 到点闹钟 + 系统通知(非 uni.createPushMessage / 个推) | **★★★ 真·离线·免服务器免通道** | **MIUI 保活(自启动/省电白名单/通知允许/精确闹钟四步)**;Android 12+ 精确闹钟要 `SCHEDULE_EXACT_ALARM` 权限 |
| **② 事件驱动·跨设备** | 老人端出事 → 通知**子女**手机 | 指标异常告警子女 | **邮件(已实现,`mailer.py` Mock / SMTP)+ app 内红点**;uni-push 在线推送**未实现**;厂商离线通道需资质不做 | 邮件 **★★★ 真送达(治关机)**;在线推送 **未实现** | 邮件 SMTP 配置;厂商离线通道要**企业资质** |
| **③ 位置驱动** | 持续移动 | 途中守护(实时轨迹/偏航) | **仍未做**;沿用"沿 polyline 模拟轨迹回放"作主兜底 | 模拟回放 **★★★ 稳**;真后台定位 **未做** | 真要做得解决保活、耗电、隧道丢星、后台定位权限 |

**这张表就是本次重排的骨架。三条结论:**

1. **最容易变真的是①(用药提醒/晨间问候),而且已经真做了。** 本地定时通知是**离线**的 —— 不需要服务器、不需要推送通道、不需要备案,系统闹钟到点就弹。这是四件事里唯一能"干净地做真"的,Android 上已落地为 `android/` 的 `AlarmManager` + 系统通知(主线程已真编通过)。**唯一的敌人是保活**(手机把 app 杀了闹钟就没了);演示机是 **MIUI**,具体就是四步引导 —— **① 自启动 ② 省电白名单 ③ 通知允许 ④ 精确闹钟**,再加前台服务兜底,不是死路。
2. **②(告警子女):邮件能真、在线推送未实现、离线要过资质门。** 当前真正落地的是 **邮件**(`mailer.py`:Mock 离线可测 / SMTP 真送达,能到关机手机)。**uni-push 在线推送尚未接入**;厂商离线通道要各家注册配 appkey、部分要**企业资质** —— 比赛队伍多半没有。所以**默认做法:邮件(真)+ app 内红点**,在线推送与离线厂商通道作为"有资质/有余力就上"的可选项。
3. **③(后台守护)仍未做。** 真后台定位没接,也没验证 —— 国产 ROM 杀后台是常态,耗电、隧道丢星、老人反感被追踪都是真问题。**保留"沿轨迹模拟回放"作为演示兜底**,真后台定位作为"真机上能做再来演,且要坦白它不稳"的加分项。

> **一句话:①已真做(🔴→🟢,`AlarmManager` 本地闹钟,真·离线),②告警子女走邮件(🔴→🟡,邮件真 / 在线推送未实现 / 离线要资质),③位置驱动仍未做(🔴→🔴,留模拟回放兜底)。三件事不再"物理不可行",但也不是"一起就真了"。**

## 1. 走 App 带来的新工程困难(这些是上一版没有、现在必须面对的)

> **⚠️ 重大修正:本项目 APK 不是 uni-app 原生编译,而是 `android/` 里一份自包含 Android 壳工程 + 原生提醒层**(`MainActivity.java` 全屏 WebView 加载云端 H5,壳**不内嵌** H5;提醒由 `AlarmScheduler` / `ReminderReceiver` / `NotificationHelper` 用 `AlarmManager` + 系统通知实现)。**主线程已用真实 aapt/javac/d8/zipalign/apksigner 本地真编通过,产出已签名 APK(com.kangle.app,versionCode 2)。** 因此下表(uni-app 原生路线)里 HBuilderX / DCloud appid / uni-push / getRecorderManager / alpha 打包兼容 等困难大多不适用 —— 打包早已跑通。真正的约束:壳已透传 mic/GPS 权限,**前台** `getUserMedia`/`geolocation` 真可用;**后台守护(③)仍未做**;跨设备只做了**邮件**,uni-push 未接入。
>
> **以下为原(uni-app 原生路线)分析,保留备查:**

从"npm 一把 `build:h5`"到"打 APK 装真机",凭空多出一整条工具链和一堆 Android 现实。逐条列,附**风险等级**与**应对**:

| # | 新困难 | 为什么是坑 | 应对 / 兜底 |
|---|---|---|---|
| 1 | **打包链路整个变了** | `uni build`(npm)只出 H5/小程序,**出不了 APK**。App 包要走 **HBuilderX + DCloud appid + 云打包**(或本地打包装 Android Studio + 签名证书)。CI 里跑不了,得人工点。 | P0 就把 appid 申请 + 云打包跑通,别拖到最后 |
| 2 | **当前是 alpha 版 uni-app** | `package.json` 锁在 `3.0.0-alpha-5020520260829001`。**App 打包工具链能不能吃这个 alpha,必须真机验证**,不能假设。HBuilderX 版本要能匹配这个 alpha。 | **P0 第一件事:hello-world APK 装机成功**,证明这条 alpha 能打 App;不行就评估锁定到稳定版 |
| 3 | **既有页面在 webview 里能不能渲染** | App 页面跑在 webview(plus 运行时)。**Leaflet(纯 DOM 地图)在 webview 里应能跑**,但真机上瓦片加载、手势缩放要验;若某页是 nvue(原生渲染)则 Leaflet 直接不可用。 | P0 spike 里把地图页装到真机点一遍;保持 vue 页面(非 nvue) |
| 4 | **录音路径要重写** | H5 用 `getUserMedia`+WebAudio 采 PCM→WAV。**App 里 `getUserMedia` 不通用**,要改 `uni.getRecorderManager()` 录 **mp3 直传**(腾讯 ASR 收 mp3,反而更省事)。但这是**第二套代码路径**,要写要测。 | 抽象出 `recorder` 适配层:H5 走 WebAudio、App 走 getRecorderManager,`asr.js` 按平台分支 |
| 5 | **一堆运行时权限** | 通知、录音、后台定位、精确闹钟(Android 12+)都要 manifest 声明 + 运行时申请;Android 13+ 通知权限**要用户手动开**,不给就静默失败。 | 首启引导页统一申请 + 权限被拒时的降级文案 |
| 6 | **保活(最烦、最不可控)** | 华为/小米/OPPO/vivo 各家杀后台策略不同。**app 被杀 → 本地闹钟不响**。这是 App 化最脏的活,**技术上无法根治**,只能:引导用户加自启动白名单 + 电池优化白名单 + 锁后台 + 前台服务(常驻通知)兜底。 | 做"保活引导"页;演示机是**小米 MIUI**,具体就四步:**① 自启动 ② 省电白名单(电池无限制) ③ 通知允许 ④ 精确闹钟** —— 装完 APK 先走一遍 |
| 7 | **厂商离线推送 filing** | 想让子女 app 被杀后也收到告警,要给 HMS/小米/OPPO/vivo 各家注册应用、配 appkey,聚合流程(如个推/uni-push)也仍要各家配置,**部分要企业资质**。 | **默认不做离线通道**,走**邮件兜底**(在线推送亦未接入);有资质再上(见 §0 结论2) |
| 8 | **真机演示依赖** | 不能像 H5 扫码即用。要一台安卓真机、装 APK、联网、授权、配好白名单。演示环境更重。 | **保留 H5 双输出**作零摩擦兜底 demo(见下) |

> **强烈建议:保留 H5 + App 双输出。** 这里"双输出"指 **H5 与 APK 两条独立下发链**(App = 原生壳 + 云端 H5,不是 uni-app 原生编译,见 §1 开头与 `android/README.md` §2.1),不是"一套代码多端出"。`build:h5` 几乎零成本继续留着,好处是:(a) 开发期大部分功能在浏览器里调,快;(b) 真机 APK 若在评委现场抽风,H5 立刻扫码兜底,演示不至于翻车。**App 只承担"必须真"的那两件(①本地闹钟、②邮件),其余照样在 H5 里也能跑。**

## 2. 你举的两个例子:路径级拆解(App 版更新)

### 2.1 通知提醒 ——「开个接口」为什么不成立(现在拆成三条真机制)

- **现状**:写 `notifications` 表 + 子女端 **5s 轮询**。只有子女 app 正开着才看得到。这不叫"及时通知"。
- **打 APK 后的真实路径,按 §0 三机制拆:**
  - **用药到点提醒(①时间驱动)**:**已真做** —— `android/` 原生 `AlarmManager` 到点闹钟 + 系统通知(`AlarmScheduler` 注册、`ReminderReceiver` 到点弹),把提醒写进系统。**离线、免服务器、真到点弹。** 敌人是保活 → MIUI 四步引导(自启动 / 省电白名单 / 通知允许 / 精确闹钟)+ 前台服务。**这是最漂亮的真机演示点。**
  - **指标异常告警子女(②事件驱动跨设备)**:老人端触发 → 后端**发邮件**(`mailer.py`:Mock 离线可测 / SMTP 真送达,能到关机手机)**+ app 内红点**。**uni-push 在线推送尚未接入**,想做"app 在线秒到"得先接 uni-push;想让"被杀也秒到"→ 配厂商离线通道(要资质,默认不做)。
  - **晨间问候(①时间驱动)**:同用药提醒,`AlarmManager` 本地闹钟每早 8 点弹;想主动外呼没开 app 的老人,叠短信(需签名报备,见 §3)。
- **诚实边界**:告警链路做成"**邮件(真,`mailer.py`)+ 红点(真)**";**uni-push 在线推送未接入**、离线厂商通道"需企业资质,未上线",都如实标注。不把未实现的东西写成已上线。
- **使用真实问题**:告警**去重降噪**(现有 `plan_helpers` 幂等要保留,别一惊一乍)、**隐私分级**(`health_level=summary` 时邮件/推送正文不能带门牌坐标)、子女**免打扰时段**、推送**点击直达**对应告警详情页(payload 带路由)。

### 2.2 散步路径 ——「高德最短路」为什么不能用(不变,与平台无关)

- **客观阻碍**:高德给 A→B **最短路**;散步要**从家出发绕一圈回家、时长可控、优先绿道/公园/少车**的**环线**。**没有消费级 API 直接给"舒适 30 分钟环线"。** 且高德步行 `/v5/direction/walking` **已实现**(`amap_service.plan_walking_2`)。
- **可行路径(分层,对应你说的"让模型规划 / 画拓扑图"):**
  1. **演示级(推荐,零风险)**:南京**预置 2–3 条精选环线**(玄武湖环湖、紫金山绿道…)做成静态 polyline/GeoJSON,直接在 Leaflet 上画,标时长/距离/景点。观感最好、运行时零风险。
  2. **半动态(你说的"让模型规划")**:LLM 结合"附近公园 POI"提若干**途经点**(家→公园入口→湖边→凉亭→家),后端对相邻点逐段调**高德步行**拼环线,校验总距离≈目标。中等工作量,是"真方法"。
  3. **拓扑图(你提到的)**:只在"已测绘的某公园内"求最优环线才需要,建小型路径图找目标长度的闭合走廊。**工作量大收益窄 → 未来,比赛不做。**
- **阉割**:连拼接都嫌重 → "家→最近公园(POI 周边搜索)→原路返回",鲁棒够用。
- **使用真实问题**:老人不照 GPS 精确走 → **定位为"推荐一段附近好走的路 + 地图",不是逐向导航**,主动降精度要求。

## 3. 逐功能可行性审计(App 版评级)

> 评级:🟢 可行 / 🟡 有坑需路径 / 🔴 仍不可行或强不建议。每条:难点 · 阻碍 · 路径 · 阉割 · 使用问题。
> **App 路线落地后的主要变化:原🔴的四件事逐条重新评级(见各条 [现状] 标注)。**

### 🟢 指标录入(log_vital)
- 数据是假的 → 存储/表单/图表纯前后端活,**可行**。
- 坑:**语音录数字**("高压178低压105")靠 ASR+LLM 抽取,易听错(178/170、方言)。录音走 H5 的 `getUserMedia`(壳已放行 mic,见 §1 开头),单一实现。
- 路径:LLM 抽成结构化 → **复述确认**("记录血压 178/105,对吗?")再落库。

### 🟢 慢病档案(add_condition)
- 纯 CRUD,**可行**。坑:老人不懂术语 → 给**常见病选择列表**,别让填 ICD。

### 🟡→🔴 分诊(assess_health)——**安全红线,最需谨慎(与平台无关)**
- **客观阻碍**:对老人说"不用去医院"**属医疗建议**,漏判急症(卒中/心梗)后果严重;法律与伦理风险,不是技术问题。
- **架构红线(必须这样做)**:
  - **分级(zone)由确定性规则决定,绝不交给 LLM**(`safety/health_rules.py`,用高血压指南等公开阈值)。LLM **只把结论讲成大白话**,不能改分级。
  - **红旗强制"紧急"**:胸痛/意识改变/言语不清/肢体无力/呼吸困难/血压≥180/120/血糖<3.9 或 >16.7 → **直接建议 120 + 通知子女**。"保健优先"**只在绿/黄区生效,永不覆盖红旗**。
  - **失败偏保守**:不确定就升级;全程"建议/参考"措辞 + 免责 + 一键 120/子女;**禁用"诊断"字样**(现有 `HealthDisclaimerGuard` 保留强化)。
- 使用问题:误报多让人不信、漏报会出事 → 阈值保守且可解释("因为您连续 5 天血压偏高")。

### 🟢 报告解读 / plain_say
- 假报告 + LLM 解读,**可行**,天然贴题。坑:LLM 过度解读 → 套免责、不下诊断。

### 🔴→🟢 用药到点提醒 —— **[App 后] 这条现在已真做,是最大升级**
- **上一版**:H5 app 没开不会响,提醒不到 → 🔴。
- **[现状]**:**本地定时通知(①时间驱动)** —— 离线、免服务器、到点弹,**专为此场景而生,🟢**。已落地为 `android/` 的 `AlarmManager` + 系统通知(已真编通过)。
- 路径:`add_medication` 落库计划 → App 端(`android/`)把每个服药点交给 `AlarmScheduler` 注册 `AlarmManager` 闹钟(Android 12+ 申请精确闹钟权限)→ 到点由 `ReminderReceiver` 弹系统通知,点击进"服药打卡"页。
- **敌人=保活**:被杀就不响 → MIUI 四步引导(自启动 / 省电白名单 / 通知允许 / 精确闹钟)+ 前台服务(常驻通知);演示机提前配好。
- 阉割:保活实在搞不定的机型,退到"打开 app 时的今日用药清单 + 打卡" + 前台常驻通知。
- 使用问题:老人漏打卡 ≠ 没吃 → 别据此误判,措辞留余地。

### 🟢 就近找医院(search_hospital)
- **高德 POI 周边搜索**(`/v3/place/around`,**待实现**)真返回、按距离排序,**可行**。坑:需老人当前城市/坐标(App 定位或档案城市兜底,App 定位比 H5 稳)。

### 🟡 挂号(register_appointment)——**是模拟,不是真挂号**
- **阻碍**:真挂号要对接微医/114/医院 HIS,需企业资质+实名+放号,**比赛拿不到**。
- 路径:**明确做成模拟预约**(生成预约单),诚实标注。去掉审批、改触发通知(§2.1)。
- 使用问题:别让评委以为真挂号 → UI 标"演示预约"。

### 🟡 公交/地铁路线(plan_route)
- **阻碍**:高德换乘 `/v5/direction/transit/integrated` **已实现**(`amap_service.plan_transit_2`);换乘结果多段(步行→公交→地铁),对老人要**极简展示**("坐 3 站在 XX 下")。
- 路径:transit 调用(`plan_transit_2`,城市+起终坐标)**已接**;余下是简化渲染;offline 兜底走 `routes.json`。
- 阉割:transit 太复杂 → 先给"打车 ETA + 一段文字怎么走"。

### 🟢 一键拨号(suggest_call / CallCard)——**已验证可行**
- `uni.makePhoneCall` 代码里已在用(`CallCard.vue` / `guardian.vue` 的 `call()`),H5 与壳内同为 `tel:` 链路 —— **壳目前不透传 `tel:`**(`MainActivity` 的 `shouldOverrideUrlLoading` 一律 `return false`,不交给系统),故壳内不会拉起拨号盘,表现与 H5 相同(要真拉起需另接 JS 桥)。放心做。
- 坑:桌面浏览器 `tel:` 无效 → 真机演示;号码从 `family_bindings`/联系人预填。
- 使用问题:本产品**情感价值最高、技术最稳**的功能 → 重点打磨(孤独识别→出按钮的时机)。

### 🔴→🟢 主动问候 / 晨间外呼 —— **[现状] app 内到点问候已真做**
