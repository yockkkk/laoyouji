## 1. 四个档位的一句话切档

**这是康乐左翼最好的演示点：同一套阈值，四种结论。** 四个剧本各对应一个分诊档位，
切换只需重跑一次 seed 脚本（一条命令，改动落在同一个库里）。

```bash
cd backend
# 先看四个剧本长什么样（不灌数据）
./.venv/Scripts/python.exe -X utf8 scripts/seed_demo.py --list

# 复位默认家庭 + 切到某个档位（ASCII key，Windows 控制台不会乱码）
./.venv/Scripts/python.exe -X utf8 scripts/seed_demo.py --scenario stable
./.venv/Scripts/python.exe -X utf8 scripts/seed_demo.py --scenario observation
./.venv/Scripts/python.exe -X utf8 scripts/seed_demo.py --scenario hypertension_spike   # 默认档
./.venv/Scripts/python.exe -X utf8 scripts/seed_demo.py --scenario emergency
```

中文档位同样收（`--level`，与 `--scenario` 互斥，二选一）：

```bash
python scripts/seed_demo.py --level 保健      # = --scenario stable
python scripts/seed_demo.py --level 观察      # = --scenario observation
python scripts/seed_demo.py --level 建议就医  # = --scenario hypertension_spike
python scripts/seed_demo.py --level 紧急      # = --scenario emergency
```

> 中文参数在 Windows 控制台容易乱码；**优先用 ASCII 的 `--scenario`**。
> 无论用哪个，`resolve_scenario` 认不出时**必须报错**、不会静默退回默认 ——
> 静默退回才是最坏的结果：你以为切到了"紧急"，屏幕上是平稳档案，你会照着
> 自己以为的那份讲下去。

不想开命令行也可以走后端接口（默认 `debug=True` 时放行，非调试环境要管理员）：

```
POST /api/seed?scenario=紧急                 # 复位 + 灌一份"紧急"档案
POST /api/seed                               # 不传 scenario，用默认（hypertension_spike）
POST /api/seed?with_persona=false            # 只要一张干净的空库（不给张桂芳灌指标档案）
```

脚本灌完**不自己念结论**：它把数从库里读回来、再喂给真规则算一遍档位，当场打印
"读回库里的数再分诊 → 实际档位"。你看到的是"库里这些数 → 这个档位"，
不是脚本背下来的一句话。

### 1.1 四个档位各要证明什么

档案共 **30 天**（`--days` 可调），日期一律相对"今天"生成。**今天只出晨起那几条读数**
（06:41–07:41 之间），因为演示是上午跑的、晚上那次还没测。

| 切档命令 | 档位 | 今天屏幕上的数 | 老人会听到什么 | 这一档想证明什么 |
|---|---|---|---|---|
| `--scenario stable` | **保健** | 血压 **138/86** | "记好了，这个数挺稳的。接着按时吃药、清淡饮食，每天散散步就行，**不用特意跑医院**。" | **康乐真正想证明的东西**：见数不撵人。30 天全在保健带里，系统照样劝老人别往医院跑 |
| `--scenario observation` | 观察 | 血压 **145/92** | "有点偏高，先别急。按时吃药、今天少盐少油，明后天再量一次，还高我再帮您约医生。" | 略高于正常时给的是**复测 + 按时服药**，不是立刻挂号 |
| `--scenario hypertension_spike` | 建议就医 | 血压 **178/105** | "号已经挂好啦，也把您的情况跟家里说了一声。" | 真该就医时才抬档，且**挂号不需要子女审批、当场办好**（见 §2 主链） |
| `--scenario emergency` | 紧急 | 血压 **186/112** 且**血氧 88%** | "这个数比较急，您先给家里打个电话，或者拨 120，别自己一个人扛着。" | 保健优先**绝不覆盖急症**：两条独立触顶路径（高血压急症 + 血氧 <90）同时成立 |

> **stable（保健）要讲透。** 这是本项目最容易被误解、也最值得讲的一档。
> 阈值刻意**偏保守地往低档收**：血压 <140/90 落"保健"，只有 ≥160/100 才抬到
> "建议就医"、≥180/110 才报"紧急"（`app/safety/health_rules.py`）。
> 台词可以是："注意 —— 这一档系统**什么都不做**，就是劝老人别去医院。
> 老人常态化的 138/86，不该惊动任何人。这正是我们这个项目要反的东西。"
> 这一档在代码里有测试钉死：`tests/test_health_api.py` 的
> `test_bp_138_86_stays_health_care`。

### 1.2 档位是怎么判出来的（评委追问时照这个讲）

档位**只由确定性规则决定，绝不交给大模型**（`app/safety/health_rules.py`，纯函数，
同输入同输出）。大模型只负责把结论讲成大白话，不能改档位。

- 血压：`≥180/110` 紧急 → `≥160/100` 建议就医 → `≥140/90` 观察 → 否则保健
- 血氧：`<90` 紧急 → `<94` 建议就医 → `<95` 观察
- 血氧/体温/血糖/心率各有一套区间；血糖还分**空腹 / 餐后**（同一个数，空腹和餐后不是一个档）
- **保健优先**：一条指标不明确越界就不抬档；但**急症有下限**，保健优先永远盖不住真危险的值

## 2. 演示脚本 · 三条链

### 主链 · 就近就医闭环（挂号 → 知会子女 → 路线 → 计划书）

演示前提：`--scenario hypertension_spike`（默认档），或不动 seed、直接对话触发。

1. **老人按住大麦克风说**："我想在南京就近看腿疼的老毛病"
   （或打字；或走首页快捷入口，它把预设话术**填进输入框**等你按发送）
   - 讲解点：模糊指令 → 自主规划

2. **左屏依次出现**（边等边讲）：

   - **步骤条**（后端 `todo_write` 的整表快照，四项）：
     ① 挂号：查本地医院、挂专家号 ② 查南京这两天的天气 ③ 规划从家怎么去医院 ④ 出一份就医出行计划书
     > 三态推进（`pending / in_progress / completed`）是后端**每一波重写整张表**
     > 推过来的，不是前端按工具调用猜的

   - **两支子智能体同时在跑**：第一波把"挂号"派给安康助手、"天气"派给银发导航，
     屏幕上先后闪出两条回报
     > 三份结构化 `report` 事件（health×1 + travel×2），各自独立作用域 ——
     > 是"真多智能体"在界面上唯一看得见的证据

   - **挂号卡（绿色，标题「专家号已预约」）**：南京鼓楼医院 · 骨科 · 邱勇（主任医师），
     挂号费 **70 元**，地址、"家人知会"那一行写的是
     **「已告诉您儿子李明（HH:MM）」** —— 不是"等待家人确认"。
     > **这里没有黄色挂起卡。** 就医不需要子女审批：挂号当场办好，办完在
     > 同一个动作里给全部绑定子女写一条**知会**。老人不该为看病等谁点头。

   - **第二波**才规划路线（目的地是第一波挂到的医院名，不是模型印象），
     银发导航出本地**公交 / 地铁 / 步行**方案（跨城的车票机票整个砍掉）

   - **计划书卡片**：标题 `张桂芳 · 南京就医出行计划书`，**共 4 页**、可打印
     | 页 | 内容 |
     |---|---|
     | 第一页 · 挂号信息 | 医院 / 科室 / 医生 / 就诊时间 / 挂号费 / 医院地址 / **状态（已办好）** |
     | 第二页 · 怎么去医院 | 从哪儿出发 / 到哪儿 / 怎么走（公交/地铁/步行）/ 用时 |
     | 第三页 · 随身清单 | 身份证、医保卡、既往病历、老花镜、常备药…（政策模板，永不留空） |
     | 第四页 · 南京天气与穿衣 | 日期 / 天气 / 气温 / 穿衣建议 / 带伞 |
     > 讲解点：每一页每一格都能追到某个工具结果里的某个键，模型不参与拼装；
     > 取不到就明写"待补"并回填 `missing`，**绝不编**。卡片脚注带模拟数据披露。

3. **台词**：“注意 —— **一分钱没花、一个真号没挂**，但这一步不是“等确认”——
   挂号在我们这里演示的是**模拟预约**，老人自己拿主意就行，**同时**他的情况已经完整
   发到了他儿子的手机上。看右边。"

4. **右屏子女端**：进「通知中心」→ **📢 长辈动态通知** 里出现那条知会，
   标题形如「【就医知会】张桂芳已挂好南京鼓楼医院骨科的号」，
   正文（`summary`）是完整的：**哪天、哪个时段、哪家医院、哪位医生、多少钱、为什么去**。
   分诊档位（如"分诊为「建议就医」"）也在里面。
   > 讲解点：这条知会是"**知道**"，不是"待办" —— 它**没有 `task_id`**，
   > 不进任何人的待办列表，点不点都一样。审批与知会在数据结构上必须能一眼分开。
   > 同一笔挂号重复下一遍也不会叠第二张卡（按 `registration_no` 幂等）。
   > **本链路全程 0 挂起**：`confirmation_tasks` 表是空的。

**这条链证明了什么**：一次真实就医的完整闭环 —— 分诊到档位 → 就近挂号 →
**知会不审批** → 本地路线 → 可打印的计划书。整条链没有一步需要子女点头，
但子女全程知情。

### 反向链 · 日常保健优先（不去医院）

这是主链的**反面**，也是康乐最想讲的一件事：**不是什么情况都让老人去医院。**

1. **老人说**："帮我记一下血压，138/86"
   > ⚠ **必须说成带斜杠的 `138/86`。** 离线剧本的血压正则只认"两个数字夹一个斜杠"
   > （`(\d{2,3})\s*/\s*(\d{2,3})`，`app/providers/llm/mock.py`）。说成
   > "高压 138 低压 86"它**一个指标都认不出来**（已实测：返回空），于是跳过
   > `log_vital` / `assess_health` 直接去挂号 —— 台上当场演成"见数就撵人"，
   > 正好把这一页要讲的**讲反**。
   > 首页「量个血压」快捷入口的预设话术就是"高压 138 低压 86"（不带斜杠），
   > **别拿它演这条链**；只拿它演"只填话、不替老人发送"那一下（见 §5）。
   > 这是离线剧本的已知边界，属于产品侧待修项，不在演示稿里掩盖。
2. **屏幕上**：`log_vital` 记下这条读数 → `assess_health` 结合 30 天档案与慢病分诊
3. **老人听到**："记好了，这个数挺稳的。接着按时吃药、清淡饮食，每天散散步就行，
   **不用特意跑医院**。"
4. **左屏「我的健康」页**（首页按钮进入）：顶部**分诊档位横幅**显示
   **「保健 · 康乐建议」**，下面一句 advice 就是上面那句。趋势图（`VitalTrend`）
   上 30 天曲线平平稳稳。
   > 档案里 30 天都落在保健带内 —— 这是 `--scenario stable` 的档案。

**这条链证明了什么**：同一套工具、同一段分诊代码，喂进**平稳**的数，结论是
"在家照顾好、别往医院跑"。**日常保健优先于就医**，不是见数就撵人。
（对照 §1.1：把 seed 切到 `hypertension_spike`，同样这句话换个数进去，
结论立刻变成"建议就医"、张罗挂号 —— 分岔点只有那个数。）

### 右翼链 · 心理健康（心里闷 → 拨号 → 活动 / 散步 / 菜谱）

1. **老人说**："一个人没意思，心里闷得慌"
2. **屏幕上先出的是「拨号卡」**（`CallCard`，`type='call'`）：卡片上有老人的原话，
   一个**大按钮**，电话号码**由后端从家人绑定关系里取、前端不拼不猜**（预填儿子李明的号码）。
   老人**点一下**才 `uni.makePhoneCall` 拉起系统拨号盘 —— 不直接跳转。
   > 讲解点：这是全产品**情感价值最高、技术最稳**的功能。孤独当下缺的是人，
   > 不是节目 —— 所以电话卡排在活动清单**前面**。
3. **接着**（老人想张罗点事）：
   - `get_recipe` → **菜谱卡**（`RecipeCard`）：一道家常菜，食材 + 分步做法，可语音朗读
   - `push_activities` → **线下活动**（棋牌室 / 养老院 / 公园 / 社区义诊）
   - `suggest_walk` → **散步环线卡**：全程几公里、连走带歇多久、在哪儿歇、
     走不动了怎么办（"路线是环的，往回走也是回家的路"）
   > 卡上脚注披露"路线是竞赛原型内置的演示数据"。

**这条链证明了什么**：右翼不是"聊天解闷"，是**把老人接回线下** —— 先接上人（拨号），
再给出门的具体去处（活动 / 环线 / 一道菜）。

## 3. 一句必须说的话：所有健康指标为合成演示数据

**答辩现场最常被追问的一句是"这数是真的吗"。答案必须是：**

> **"指标是合成的，但每个数都经得起追问 ——
> 时刻不是一个整点、七天不是一个值、今天不是几个月前、血压有昼夜节律。"**

这句话要放在**显眼处**：开场就主动交代，不要等评委问。依据（全部可在代码里指认）：

| 说法 | 依据（代码位置） |
|---|---|
| **所有的数是合成的** | `app/db/seed.py` 的 `seed_kangle_persona`：按内容派生的确定性随机（md5 种子 `用户名\|指标\|日期`）生成，是演示档案，**不是真人病历**。README / 计划书脚注 / 本文都写着 |
| **时刻不是一个整点** | 测量钟点从 `_AM_CLOCKS` / `_PM_CLOCKS` / `_GLU_*` / `_HR_*` / `_SPO2_*` / `_TEMP_*` / `_WEIGHT_*` 里飘选，**全库没有任何一条读数落在整点或半点**（清一色 08:00 是"一眼假"的头号特征） |
| **七天不是一个值** | 每条血压是一个独立的日子生成的（`_rng(who, "bp_s", day)`），七天七个值，不存在"一个值重复七天" |
| **今天不是几个月前** | 日期一律相对"今天"生成（`day0 = today or date.today()`），不写死；**演示当天早上跑一次**，时间线收尾就是当天 |
| **血压有昼夜节律** | 睡前那次收缩压落 3–7、舒张压落 1–3（`_readings_for_day` 的 `bp_pm_*`）—— 晨起偏高、午后回落，两条不相交的钟点池 |
| **数值站得住** | 收缩压恒 > 舒张压；血氧不超 100%；每条读数的档位与数值自洽（不会"178/105 标着保健"）。`tests/test_demo_scenarios.py` 逐条钉住 |

> 主动交代这件事**反而体现工程严谨** —— 把"造假质疑"转成"这份数据是按临床逻辑
> 一项项反推出来的"。评委真去翻时间线，会发现 30 天里还**刻意漏测了几天**
> （`_MISSED_OFFSETS`：老人不是机器，出门了/血压计没电了/就是忘了），
> 具体漏了哪几天，`seed_demo.py` 复位时会打印出来给答辩者兜底（`scripts/seed_demo.py:68-69`）。
> 这处细节比任何辩解都管用。

## 4. 诚实边界：哪些是真的、哪些是模拟的、哪些离线跑不了

**宁可写保守，也不要把"我改了代码"说成"功能能用了"。** 这一节答辩时主动讲。

### 4.1 真的（可当众指认、离线也能跑）

- **分诊规则**：`app/safety/health_rules.py` 纯函数，四档阈值 + 症状红旗，有单元测试逐条钉死
- **数据存储与同源**：指标入库；"手机点一下记血压"和"跟康乐说血压 178/105"**落在同一段代码上**
  （同一档、同一 display），有测试守（`test_rest_and_chat_agree_on_the_same_reading`）
- **就医知会**：挂号办完写一条 `appointment_notice`，完整、幂等、**无 `task_id`**（知会不是审批）
- **本机可跑的链路**：旗舰全链路、四个档位切档、右翼三张卡（拨号/菜谱/散步环线），
  mock LLM + local 存储下全离线可复现
  > 《社区活动推荐单》**不在这条离线清单里**：它是 `compose_deliverable(kind='community_card')`
  > 的交付物，形态就是一张卡片 —— `plan_builder.build_community_card` 返回 `"type": "community_card"`，
